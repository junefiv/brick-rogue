# 개발 철학

이 프로젝트의 가장 중요한 원칙은 세 가지다.

### 1. 벽돌깨기의 본질을 훼손하지 않는다.

게임의 기본 단위는 항상 다음과 같다.

`조준 → 공 발사 → 모든 공 복귀 → 벽돌 하강 → 신규 벽돌 생성`

별도의 방으로 이동하거나 캐릭터가 맵을 걸어 다니지 않는다.

---

### 2. 로그라이크의 성장은 XP와 빌드에서 발생한다.

라운드가 일정 횟수 지났다고 자동 강화하지 않는다.

`벽돌 파괴 → XP 획득 → 레벨업 → 3택1 → 스킬 성장 → 스킬 융합`

구조를 사용한다.

---

### 3. 공 개수와 화면 연출이 증가해도 게임이 무너지지 않아야 한다.

이 게임에서 가장 위험한 기술적 문제는 다음이다.

`공 증가`
→ `충돌 증가`
→ `스킬 이벤트 증가`
→ `Particle 증가`
→ `Sound 증가`
→ `CPU/GPU 부하 폭증`
→ `프레임 드롭`

따라서 성능 최적화는 출시 직전에 하는 작업이 아니다.

**게임 시스템 자체에 연산량 상한을 설계한다.**

# 1.4 세계관과 분위기

스토리를 강하게 소비하는 게임은 아니다.

세계관은 게임의 시각적 통일성과 콘텐츠 확장을 위한 장치로 사용한다.

### 세계관

거대한 인공 에너지 시설인 **CORE** 내부에 정체불명의 Corruption이 발생한다.

Corruption은 기하학적 Block 형태로 Core 내부를 침식한다.

플레이어는 Core 내부에 설치된 방어 프로그램을 조작하여 Energy Orb를 발사하고 침식을 제거한다.

### 분위기

* Neon
* Sci-Fi
* Cyber
* Digital
* Minimal
* Arcade

캐릭터 애니메이션보다:

* 공
* 벽돌
* 빛
* 충돌
* 폭발

이 게임의 주인공처럼 보이도록 한다.

# 1.6 핵심 재미

게임의 핵심 재미는 5개다.

## ① 최적의 각도 찾기

벽과 벽돌 사이에 공을 집어넣어 최대한 많은 충돌을 만드는 재미.

---

## ② 점점 미쳐가는 공

초반:

`공 8개 / 데미지 1`

후반:

`공 80개 + 관통 + 번개 + 폭발 + 독 + 반사 강화`

같은 형태가 된다.

---

## ③ 빌드 선택

레벨업 때마다:

* 현재 빌드 강화
* 새로운 계열 진입
* Fusion 준비

중 무엇을 선택할지 고민한다.

---

## ④ 스킬 융합

Lv5 스킬 두 개를 결합한다.

예:

`폭발 Lv5 + 관통 Lv5`

↓

**관통 폭탄**

기존 슬롯 2개가 슬롯 1개로 압축된다.

---

## ⑤ 화면 삭제 쾌감

게임 후반에는 잘 완성된 빌드가 연쇄 작용하여:

`한 번 발사 → 수십 개 벽돌 파괴`

가 일어나는 순간을 만든다.

---

# 1.7 차별화 요소

기존 벽돌깨기는 일반적으로:

`공 개수 증가 + 벽돌 HP 증가`

에 집중한다.

ROGUE BREAKER는:

`Ball Physics + Passive + Active + Fusion + Build`

에 집중한다.

특히 핵심 USP는:

### Skill Compression

두 개의 스킬을 융합하면 하나의 스킬로 압축된다.

따라서 플레이어는:

`스킬 획득 → 레벨업 → 융합 → 슬롯 확보 → 추가 스킬 획득`

이라는 성장 사이클을 반복한다.

# 2.2 Round 정의

**공을 한 번 발사하고 모든 공이 돌아올 때까지 = 1 Round**

Round는 시간이 아니다.

게임의 턴이다.

---

# 2.3 조작 방법

기본 조작은 한 손을 기준으로 한다.

### Aim

화면을 누르고 Drag.

### Aim Guide

예상 첫 번째 충돌까지 궤적 표시.

초기에는 1회 반사 정도까지 Guide를 표시한다.

### Fire

손을 놓으면 발사.

---

# 2.4 발사 각도 제한

지나치게 수평으로 발사하여 공이 수십 초 동안 벽 사이에서 튀는 문제를 막는다.

최소 발사각:

약 **10°**

정확한 값은 플레이 테스트로 결정한다.

---

# 2.5 Ball Return

모든 공은 하단 Return Line으로 돌아온다.

첫 번째로 돌아온 공의 X좌표를 다음 Round 발사 위치로 사용한다.

따라서 플레이어는:

현재 공격 각도뿐 아니라

**다음 Round 발사 위치**

도 고려해야 한다.

---

# 2.6 이동·전투·탐험

캐릭터 직접 이동 없음.

전통적인 맵 탐험 없음.

대신:

**Ball Trajectory 자체가 공간 플레이**

역할을 한다.

플레이어 전략:

* 어느 벽돌부터 제거할지
* 좁은 틈을 노릴지
* Active를 사용할지
* 다음 발사 위치를 어디로 만들지

---

# 2.7 Active 조작

Active 최대 슬롯:

**4개**

화면 하단에 배치.

```text
[💣] [⚡] [🌀] [❄]
 3   READY  1    5
```

숫자는 남은 Round Cooldown.

Active는 기본적으로:

**Aim Phase에서만 사용**

한다.

공이 날아가는 중에는 새로운 Active를 사용할 수 없다.

복잡한 실시간 입력과 상태 충돌을 방지하기 위함이다.

# 14.11 Weighted Ball

Logical 192.

Physical 96이면:

각 Physical Ball:

Weight 2.

기본 Damage:

3.

충돌 Damage:

`3 × 2 = 6`

---

# 14.12 확률 보정

Weight가 3인 Ball이 Explosion 10%를 가졌다고 하자.

단순하게:

30%

로 만들지 않는다.

다음 공식을 사용한다.

`AdjustedP = 1 - (1 - P)^Weight`

P = 0.1.

Weight = 3.

약:

27.1%.

이렇게 해야 실제 Ball 3개의 Proc Probability와 유사해진다.

---

# 14.13 그룹 분열

Ball Group을 분리한다.

단 Physical Cap을 넘으면:

새로운 Node를 만드는 대신 Weight를 재분배하거나 대표 궤적만 추가한다.

# 14.14 Ball Node

```text
velocity
weight

```

BallSimulation 하나가 전체를 업데이트한다.

Godot의 범용 RigidBody 충돌 시스템에 핵심 Ball Simulation을 전적으로 맡기지 않는다.

뿐이다.

사용.

단순히 Frame마다 위치 이동 후 Overlap만 검사하지 않는다.

Explosion + Pierce.

Explosion + Frost.

Explosion + Critical.

같은 Skill이 여러 방향으로 진화 가능하게 한다.

# 최종 게임 정의

ROGUE BREAKER는 단순히:

**벽돌깨기에 로그라이크 카드 선택 UI를 붙인 게임**

이어서는 안 된다.

Run이 진행됨에 따라 플레이 방식 자체가 달라져야 한다.

초반:

```text
8 Balls
Basic Bounce
```

중반:

```text
30 Balls
Pierce
Explosion
Lightning
```

후반:

```text
Thunder Swarm
Penetration Bomb
Chrono Loop
Gravity Salvo
```

그리고 플레이어가 Run 종료 후:

> 이번 판은 관통 폭탄이랑 뇌우를 합쳐서 화면을 다 밀어버렸다.

처럼 **자기가 만든 Build를 기억하게 만드는 것**이 목표다.

# 개발 시작 전 반드시 검증할 4가지

### ① 기본 벽돌깨기가 재미있는가?

로그라이크가 없어도 공을 튕기는 것 자체가 재미있어야 한다.

### ② 300 Logical Ball 상황을 버틸 수 있는가?

여기서 실패하면 콘텐츠 개발을 진행하지 않는다.

### ③ Passive 5개 정도만으로 플레이 감각이 달라지는가?

숫자만 커지는 Skill이면 실패다.

### ④ 첫 Fusion 순간이 강한 보상이 되는가?

플레이어가:

**“다음 판에는 다른 Fusion을 만들어보고 싶다.”**

라고 느껴야 한다.

이 네 항목을 먼저 통과시킨 다음 Boss, Meta, BM, Daily 등을 붙이는 것이 이 프로젝트의 올바른 개발 순서다.
