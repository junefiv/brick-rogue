# 기획 분석과 개발 계획

## 판단

핵심 차별점은 벽돌깨기 물리 위에 얹는 **빌드 선택과 슬롯 압축**이다. 별도 캐릭터·맵 이동이 없고 입력이 조준 단계에 집중되어 있어 1인 개발에 적합한 중심 구조를 갖고 있다. 반면 18 패시브×8 액티브×10 융합, 보스 4종, 메타 성장, 백엔드, 결제를 동시에 완성하는 범위는 크다. 출시 항목과 재미 검증 항목을 분리해야 한다.

현재 구현은 원본 문서의 1~2주차 물리/성능 기반과 3~5주차 성장/융합의 일부를 한 번에 체험할 수 있도록 연결한 프로토타입이다. 제품 출시 완료를 의미하지 않는다.

## 개발 전 확정해야 할 설계 충돌

### 1. 예상 레벨과 융합 횟수

모든 스킬을 Lv1부터 카드로 얻으면 기본 스킬 두 개를 Lv5로 만들기 위해 카드 선택 10회가 필요하다. Lv16~22에서는 총 카드 선택 15~21회뿐이다. 2~4개의 융합을 목표로 하면 원본 4~8개 스킬에 최소 20~40회의 선택이 필요하며, 다른 스킬과 융합 후 강화에 쓸 선택은 별도다.

프로토타입은 원본 레벨·XP 규칙을 유지한다. 테스트 랩으로 완성 빌드를 시험한다. 다음 밸런스 단계에서 아래 중 하나를 플레이테스트로 결정해야 한다.

- 첫 융합 목표를 1개로 줄이고 2개를 숙련자 목표로 삼는다.
- 보스 보상에 선택 강화 횟수를 추가한다.
- 기본 스킬 최대 레벨이나 레벨업 빈도를 조정한다.

### 2. Round 40의 의미

라운드 40에 보스가 생성되면 같은 라운드에 반드시 죽지 않는다. 이 구현은 **40라운드에 최종 보스 등장, 이후 처치 시 클리어**로 해석했다. 보스가 살아 있으면 계속 내려오며 위험선을 넘으면 패배한다.

### 3. 동결과 그리드 겹침

동결 벽돌이 멈추는데 위 벽돌이 무조건 내려오면 두 벽돌이 같은 칸을 차지한다. 현재 아래부터 하강시키고, 동결 벽돌이 막고 있는 열은 위쪽 벽돌도 멈춘다. 동결 스킬의 가치가 한 칸을 넘어선다는 점을 밸런스에 반영해야 한다.

### 4. 가중 공은 완전 동일한 물리가 아니다

300 논리 공을 96개 궤적으로 묶으면 총 가중 피해를 유지할 수 있지만, 실제 공 300개의 독립된 관통·반사·치명타 경로와 완전히 같지 않다. 현재 가중치 합 300과 보정 확률 `1-(1-p)^weight`를 적용한다. 이후 Split/유도 스킬은 별도의 그룹 분리 정책이 필요하다.

### 5. 모바일 성능 판정

PC headless 시뮬레이션 수치와 휴대폰 전체 프레임 시간은 다르다. 120Hz 시뮬레이션을 60FPS로 렌더링하면 프레임당 기본 2스텝, 4배 가속이면 최대 8스텝을 실행한다. 물리 스텝 평균만 보고 60FPS 달성이라고 결론 내리면 안 된다.

### 6. 스킬 재획득과 분해

현재 융합으로 소비한 원본 스킬은 빈 슬롯이 있으면 다시 카드 풀에 들어갈 수 있다. 단, 이미 원본을 다시 보유한 상태에서 분해하면 레벨/슬롯 처리 충돌이 생길 수 있으므로 분해는 원본을 보유하지 않을 때만 허용한다. 융합 강화 레벨은 분해 시 사라지고 원본 둘은 Lv5로 복구한다.

## 기술 선택

- Godot 4.7.2 공식 안정 버전을 사용했다. [공식 배포 페이지](https://godotengine.org/download/archive/4.7.2-stable/)
- Windows에서 Android 네이티브 APK를 내보낸다. Java 17, Android SDK, 공식 템플릿을 사용한다. [공식 Android 내보내기 문서](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html)
- 한글 폰트와 벡터 도형만 사용해 외부 미술 의존성을 줄였다.
- 로컬 오프라인 플레이부터 검증하며 클라우드 프로젝트/키 없이 동작한다.
- Supabase는 이후 Adapter로 연결한다. 클라이언트에는 공개 키만 두고, 사용자 데이터는 RLS, 중요 재화는 서버 검증, 오프라인 저장과 동기화 충돌 정책이 필요하다. 지금 연결됐다고 표시하는 UI는 없다.

## 다음 개발 순서와 통과 기준

| 단계 | 내용 | 통과 기준 |
|---|---|---|
| 1. 휴대폰 물리 QA | 조준, 모서리, 얕은 각도, 가속, 복귀 | 공 끼임/복귀 실패/잘못된 하강 재현 없음 |
| 2. 지속 부하 QA | 300 논리 공, LOW/BAL/HIGH, 15분 실제 실행 | 목표 기기 30FPS 장기 하락·과열·메모리 증가 확인 및 개선 |
| 3. 초기 성장 밸런스 | 첫 레벨업, 멀티볼 필요도, 첫 융합 시간 | 기본 게임의 재미와 빌드 차이를 플레이어가 설명할 수 있음 |
| 4. 콘텐츠 | 나머지 스킬과 원본 Fusion 레시피, 보스별 패턴 | 스킬 상호작용과 슬롯 테스트 확장, 40라운드 실제 클리어 |
| 5. 저장 강화 | 버전 마이그레이션, 백업 파일, 앱 라이프사이클 | 앱 종료/복구/손상/업데이트 시 데이터 일관성 |
| 6. 백엔드·메타 | Supabase 인증/클라우드 저장/검증된 결과 업로드 | 오프라인 실패 처리, RLS, 재화 중복 방지 검사 |
| 7. 배포 | AAB, 출시 서명, 스토어 요구사항, 광고/IAP | 실기기·스토어 테스트 트랙 통과 |

## 알려진 프로토타입 제한

- 전투와 UI 일부는 단일 파일에 모여 있다. 기능이 늘면 RoundManager/ActiveSystem/Presentation으로 추가 분리한다.
- 이벤트는 정해진 개수씩 분할 처리한다. 해소 전 다음 라운드를 시작하지 않는다. 큐 길이 hard cap으로 피해를 버리지는 않는다.
- 연쇄는 보수적이다. 일반 폭발/번개가 서로 다시 발동하지 않는다. 폭발 벽돌의 파괴 연쇄만 깊이 4 이내에서 이어진다.
- 액티브 강화의 수치와 애니메이션은 초기값이다. 타임 스톱/빙결은 주로 쿨다운이 개선된다.
- 랩은 현재 63개 일반 고HP 벽돌이다. 실드/보스/위치 왜곡/분열이 섞인 최악 조건은 아직 추가 검증 대상이다.
- 재생 효과음은 합성한 간단한 한 종류다. 다채로운 오디오 콘텐츠와 BGM은 아직 없다.
- 글자 렌더링은 폰트 캐시를 사용하지만 사전 생성된 숫자 아틀라스는 아니다. 저사양 기기 프로파일 후 필요하면 바꾼다.
- 앱 시작 저장은 임시 파일을 쓴 뒤 교체한다. 저장 이중화와 구조별 상세 검증은 더 강화할 수 있다.
