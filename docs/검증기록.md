# 검증 기록 · 0.4.0

0.4.0 추가 검사: 신규 규칙 21개 통과, 114종 VFX 장면 렌더링 통과. 원본 SVG·스프라이트 아틀라스·GPU 파티클·셰이더·Tween과 고정 풀을 사용한다. Windows 20초 화면 부하 측정은 평균 28.75FPS다. SM-F966N에 0.4.0 업데이트 설치와 실행을 확인했으며 실행 직후 로그에 스크립트·셰이더·치명적 오류는 없었다. 장시간 모바일 전투 성능 검사는 남아 있다. 아래 0.2.0/0.3.0 실기기 기록은 과거 버전 기록이다.

UI 테스트는 엔진 입력 이벤트로 포인터 누르기/떼기를 재현한 것이다. 실제 Android 터치 패널 테스트는 아니다.

## 부하 검증의 구분

### 일반 순차 발사 시뮬레이션

`stress-sequential.json`은 최적화 전 측정한 기준값이다. 300 논리 공 / 96 실제 공 상한 / 고HP 벽돌 63개 / 120Hz로 900초 분량을 약 100초에 계산했다. 동시 공의 실제 최대치는 61개였다. 54번 발사, 139,676번 충돌, 이벤트 큐 최대 196개를 기록했다. 평균 물리 스텝 0.93ms, p95 3.69ms였다.

### 지속적으로 실제 공 96개 유지

최종 코드는 돌아온 공을 매 스텝 다시 채워 96개를 유지하는 합성 부하 검사를 별도로 실행한다. `stress-final.json`에 결과를 기록한다. 실제 플레이의 순차 발사보다 강한 조건이며 900초는 **시뮬레이션 시간**이다. 휴대폰에서 15분간 실제 실행한 검사가 아니다.

최종 결과: 900초 분량을 약 380초에 완료했다. 실제 공 최대 96개, 벽돌 63개에서 **1,010,407회 충돌**, 이벤트 큐 최대 1,817개를 기록했다. 평균 스텝 3.51ms, p95 5.69ms, p99 7.26ms, 단일 최악 스텝 55.35ms였다. 상한 초과와 크래시 없이 끝났으나 최악 스텝과 4배 가속 비용은 추가 최적화 대상이다.

타이밍 기록용 배열 자체가 메모리를 사용하므로 시작 대비 메모리 증가를 곧바로 누수로 판정하지 않는다. 장시간 실기기 메모리 검증은 별도로 필요하다.

### 화면을 포함한 검사

Windows AMD OpenGL 환경에서 20초 실제 렌더링 + 다른 프로세스의 강한 부하를 동시에 실행한 초기 측정은 약 26FPS였다. 초기 결과로 60FPS 목표 달성을 선언할 수 없다. 정확한 최종 화면 검사 값은 `render-final.json`에 기록한다. GPU/드라이버·동시 부하의 영향이 있어 Android 성능값으로 대체할 수 없다.

0.2.0의 스킬별 효과를 포함한 단독 실행 측정은 평균 25.07FPS, 관측 최악 프레임 57.70ms, 물리 콜백 최대 2.66ms였다. 종료 시 오디오 자원 누수 경고는 재현되지 않았다. 이 호스트의 화면 포함 성능은 60FPS 목표에 미달한다. 모바일에서는 실제 프로파일링을 통해 렌더링·프레임 동기화·가속 비용을 구분해서 검증해야 한다.

## 적용한 최적화

- 300개 논리 공을 최대 64/96/128개 계산 공으로 분리, 가중치 합 보존
- 그리드 후보 검색과 이동 경로 경계의 빠른 거부 후 정밀 swept circle 계산
- 번개 대상의 거리는 정렬 비교마다 다시 계산하지 않고 후보당 한 번만 계산
- 전투 이벤트는 스텝당 256개씩 처리하고 잔여 이벤트는 다음 스텝에 보존
- 2차 효과의 자기 재발동 차단, 폭발 벽돌 연쇄 깊이 4
- 표시 효과 생성 예산 및 총 표시 개수 제한, UI 스타일 캐시
- 충돌 효과음 합산 재생 및 80ms 간격, 종료 시 재생 자원 정리

## 추가로 필요한 실제 기기 검사

0.2.0 APK는 `SM-F966N`(Android 16)에 기존 패키지를 제거한 뒤 설치했다. versionCode 2와 versionName 0.2.0을 기기에서 확인했으며, 런처 실행 후 프로세스와 포커스된 Godot 액티비티를 확인했다.

0.3.0 APK도 같은 기기에 새로 설치했다. versionCode 3과 versionName 0.3.0을 확인했고, 1080×2520 실제 화면 캡처에서 안전 영역의 세로 전체 사용, 구매 카드, 스킬 설명 패널이 잘리지 않는 것을 확인했다.

1. 첫 발사, POINT 공 구매, 앱 재진입
2. 화면비·노치·내비게이션 영역과 터치 좌표
3. LOW/BAL/HIGH에서 15분 이상의 FPS·발열·메모리
4. 모서리 연속 충돌, 가속 시 전 공 복귀, 연쇄 스킬
5. 전체 40라운드 난이도 및 최종 보스 클리어

개발 호스트에서는 Godot가 Windows 인증서 저장소를 읽지 못했다는 경고를 출력했다. 프로젝트는 오프라인이며 위 검사에서 게임 스크립트 오류는 발생하지 않았다. 온라인 기능 검증 결과로 해석해서는 안 된다.
